# 星联合健康保险 A2A 智能理赔助手 — 设计文档

> 版本：v1.0  
> 基于元保三Agent架构、慧择小马理赔、太保灵析、国任轻量化改造等行业实践融合设计  
> 核心原则：**Agent 协同处理 + 人工最终授权，效率与风控并重**

---

## 一、总体架构：5-Agent A2A 协同链路

```
┌─────────────────────────────────────────────────────────────────┐
│                        用户层                                    │
│  小程序/H5/APP 报案入口 → 自助上传影像 → 进度查询 → 结果确认    │
└────────────────────────────┬────────────────────────────────────┘
                             │
┌────────────────────────────▼────────────────────────────────────┐
│                    A2A Agent Mesh 协同层                        │
│                                                                │
│  ┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐   │
│  │ 报案受理 │──▶│ 材料解析 │──▶│ 核责判断 │──▶│  理算   │   │
│  │ Agent A  │   │ Agent B  │   │ Agent C  │   │ Agent D  │   │
│  └──────────┘   └──────────┘   └──────────┘   └──────────┘   │
│       │              │              │              │           │
│       │              │              │              │           │
│       ▼              ▼              ▼              ▼           │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │              风控审查 Agent E                           │   │
│  │  反欺诈检测 + 历史比对 + 异常标记 + 置信度评分          │   │
│  └─────────────────────────────────────────────────────────┘   │
│                             │                                   │
│                             ▼                                   │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │              结论汇总 Agent F                           │   │
│  │  汇总全链路Agent输出 → 生成审核报告 → 推送到人工节点     │   │
│  └─────────────────────────────────────────────────────────┘   │
└────────────────────────────┬────────────────────────────────────┘
                             │
┌────────────────────────────▼────────────────────────────────────┐
│                    人工授权 Gate（强制节点）                      │
│  ┌──────────────────────────────────────────────────────────┐  │
│  │  ● 审核看板：全链路Agent推理过程可追溯                      │  │
│  │  ● 一键操作：通过 / 驳回（附理由）/ 修改后通过              │  │
│  │  ● 风险分层：绿灯(自动建议) / 黄灯(建议人工重点审核)        │  │
│  │  ● 操作留痕：所有人工操作记入审计日志                       │  │
│  └──────────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────────┘
```

### 1.1 设计理念

| 维度 | 说明 |
|------|------|
| **A2A 协同** | 各 Agent 通过标准化消息协议通信，前一 Agent 输出作为后一 Agent 输入上下文 |
| **可追溯** | 每个 Agent 的推理过程、中间结果、置信度全部持久化，供人工审核回溯 |
| **渐进式自动化** | 简单案件全自动处理生成建议，复杂案件自动标记转人工 |
| **人工兜底** | 所有理赔最终结论必须经过人工授权节点，AI 仅做辅助决策 |
| **轻量化落地** | 参考国任模式，分阶段实施，首期聚焦 1-2 个险种 |

## 二、Agent 详细设计

### 2.1 Agent A：报案受理 Agent

**定位**：用户触达的首个节点，完成报案信息采集与案件初始化

| 项 | 说明 |
|----|------|
| **输入** | 用户提交的报案信息（出险人、险种、出险时间、出险描述）+ 影像材料 |
| **能力** | ① 引导式问卷采集报案信息 ② 影像格式/清晰度前置校验 ③ 生成唯一案件编号 ④ 初始化案件状态机 |
| **输出** | 结构化报案记录（JSON）+ 案件上下文对象（CaseContext） |
| **参考对标** | 国任"客户自助理赔模块"、慧择"材料解析前置" |
| **技术选型** | 前端表单 + 文件上传服务 + 案件管理服务 |

**关键设计**：
- 影像前置校验：实时检测模糊、反光、残缺、翻拍，不合格即时提示重拍
- 报案信息支持渐进式采集：先收核心信息（谁、何时、何病），材料可在后续补充

### 2.2 Agent B：材料解析 Agent

**定位**：核心智能环节，将非结构化影像转化为结构化理赔数据

```
┌────────────────┐    ┌─────────────────┐    ┌─────────────────┐
│  影像预处理     │───▶│  多模态信息提取  │───▶│  结构化输出      │
│  · 图片增强     │    │  · OCR 文字识别  │    │  · 就诊日期      │
│  · 分类归档     │    │  · 关键字段抽取  │    │  · 诊断结论      │
│  · 质量过滤     │    │  · 费用明细解析  │    │  · 医疗费用清单   │
└────────────────┘    └─────────────────┘    └─────────────────┘
```

| 项 | 说明 |
|----|------|
| **输入** | 影像材料（发票、费用清单、诊断证明、病历、身份证明等） |
| **能力** | ① OCR 文字识别 ② 多模态大模型关键信息提取 ③ 影像自动分类归档 ④ 费用明细结构化 |
| **输出** | 结构化医疗数据（MedicalRecord）+ 材料清单（DocumentIndex） |
| **参考对标** | 元保"事件整理Agent"、太保灵析"1分钟自动提取"、中再寿险"单证分类+信息抽取" |
| **技术选型** | OCR（PaddleOCR/Tesseract）+ 多模态大模型（GLM-4V/Qwen-VL）+ 字段提取模型 |

**关键设计**：
- 置信度标记：每个提取字段附带置信度分数，低置信度字段在结论报告中高亮
- 多模态优先：优先使用多模态大模型直接理解影像内容（发票、诊断证明），OCR 作为兜底
- 敏感信息脱敏：身份证号、银行卡号等在提取后即时脱敏，仅授权人员可见

### 2.3 Agent C：核责判断 Agent

**定位**：保险责任判定核心，基于 RAG 技术实现条款匹配

```
┌────────────────┐    ┌─────────────────┐    ┌─────────────────┐
│  条款知识库     │    │  责任匹配引擎    │    │  核责结论输出    │
│  · 保单条款向量 │───▶│  · 出险事件分析  │───▶│  · 责任归属      │
│  · 免责条款索引 │    │  · 免责条款比对  │    │  · 排除条款检查  │
│  · 理赔规则库   │    │  · 等待期校验    │    │  · 置信度评分    │
└────────────────┘    └─────────────────┘    └─────────────────┘
```

| 项 | 说明 |
|----|------|
| **输入** | 结构化医疗数据（MedicalRecord）+ 保单信息 |
| **能力** | ① 基于 RAG 的条款语义检索与匹配 ② 等待期/观察期校验 ③ 免责条款逐条比对 ④ 既往症识别 |
| **输出** | 核责判断报告（LiabilityReport）：责任归属结论 + 排除项检查 + 置信度 |
| **参考对标** | 元保"核责Agent"、中再寿险"责免分析Agent" |
| **技术选型** | RAG（向量检索 + 重排序）+ LLM 推理 + 规则引擎（Drools 兜底） |

**关键设计**：
- **RAG + 规则双引擎**：LLM 做语义理解，规则引擎做确定性逻辑（如等待期天数硬校验）
- **条款版本管理**：每个理赔案件关联出险时刻的保单条款版本，避免条款更新导致的误判
- **免责条款逐条声明**：输出中必须逐条列示免责条款的匹配结果，不可遗漏

### 2.4 Agent D：理算 Agent

**定位**：自动化理算核心，计算赔付金额

| 项 | 说明 |
|----|------|
| **输入** | 核责判断报告 + 结构化费用明细 + 保单费率表 |
| **能力** | ① 费用分类与可赔项识别 ② 免赔额/免赔率计算 ③ 赔付比例应用 ④ 分项/汇总理算 |
| **输出** | 理算明细单（CalculationDetail）：分项理算表 + 赔付总额 + 理算依据说明 |
| **参考对标** | 中再寿险"理算Agent"、慧择"理算核算" |
| **技术选型** | 规则引擎 + LLM 审核 + 计算模块 |

**关键设计**：
- 分项理算明细细化到每一条费用条目（药品费、检查费、治疗费等）
- 理算依据可追溯：每项金额的计算公式、引用的条款编号全部记录
- 支持理算预案：如有条款歧义，输出多套理算方案供人工选择

### 2.5 Agent E：风控审查 Agent

**定位**：安全兜底环节，防范欺诈风险

| 项 | 说明 |
|----|------|
| **输入** | 全链路 Agent 输出 + 历史理赔数据 + 外部黑名单 |
| **能力** | ① 反欺诈规则匹配 ② 历史理赔记录比对 ③ 就诊机构异常检测 ④ 短期出险预警 |
| **输出** | 风控报告（RiskReport）：风险评分 + 风险标签 + 建议操作 |
| **参考对标** | 暖哇科技"天鉴"调查智能体 |
| **技术选型** | 规则引擎 + 图数据库（关联查询）+ 异常检测模型 |

**关键设计**：
- 风险分层输出：绿灯（低风险，AI建议通过）/ 黄灯（中风险，建议人工重点审核）/ 红灯（高风险，建议拒赔或调查）
- 首次出险 vs 多次出险分组处理逻辑

### 2.6 Agent F：结论汇总 Agent

**定位**：面向人工授权节点的信息整合与呈现层

| 项 | 说明 |
|----|------|
| **输入** | Agent A~E 的全部输出 |
| **能力** | ① 多 Agent 输出聚合与冲突消解 ② 审核报告自动生成 ③ 风险等级综合评定 ④ 推送至人工授权工作台 |
| **输出** | 完整理赔审核报告 + 操作建议 + 置信度汇总 |
| **参考对标** | 元保"结论解读Agent"、中再寿险"报告生成Agent" |

**关键设计**：
- **冲突消解**：当核责 Agent 与理算 Agent 输出不一致时，在报告中明确标注分歧点
- **置信度汇总**：用直观的可视化方式（进度条/色块）展示全链路置信度
- **报告精简模式**：默认展示一页摘要，详情逐层可展开

## 三、A2A 通信协议设计

### 3.1 Agent 间消息格式

```json
{
  "messageId": "msg_20240724_001",
  "sourceAgent": "agent_b_doc_parser",
  "targetAgent": "agent_c_liability",
  "caseId": "CL202407240001",
  "messageType": "result_forward",
  "timestamp": "2024-07-24T10:30:00+08:00",
  "payload": { /* Agent-specific output */ },
  "context": {
    "confidence": 0.95,
    "processingTimeMs": 3200,
    "traceId": "trace_abc123"
  }
}
```

### 3.2 Agent 编排策略

| 模式 | 适用场景 | 说明 |
|------|----------|------|
| **串行** | A→B→C→D→E→F | 默认模式，前一Agent输出作为后一Agent输入 |
| **并行** | B(材料解析) 完成后 C+D 并行 | 核责和理算可同时进行（依赖数据不冲突时） |
| **回退** | Agent 输出置信度 < 阈值 → 回退到上一步补充信息 | 如材料不清晰→通知用户重新上传 |
| **终止** | 核责判定明显不在保障范围内 → 提前终止并生成拒赔建议 | 避免后续 Agent 无效计算 |

### 3.3 状态机定义

```
报案已提交 → 材料解析中 → 核责判断中 → 理算中 → 风控审查中 → 
结论汇总中 → 待人工授权 → 已完成(通过/驳回/修改后通过)
                                    ↘ 退回补充材料 → 材料解析中
```

### 4.2 授权规则

| 案件类型 | AI 置信度 | 处理方式 |
|----------|-----------|----------|
| 简单案件（门诊、小额） | ≥ 90% | AI 自动生成"建议通过"，人工一键确认 |
| 普通案件 | 70% ~ 89% | 人工需逐项审核关键字段后确认 |
| 复杂案件（住院、大额） | < 70% 或 风控黄灯/红灯 | 强制人工全流程审核，AI 结果仅作参考 |
| 任何案件 | AI 建议拒赔 | 自动升级至资深核赔人员审核 |

### 4.3 审计日志

所有操作全量记录，支持事后稽查：

## 五、分阶段实施路线图

### Phase 1：MVP 试点（6~8 周，参考国任模式）

| 模块 | 投入 | 产出 |
|------|------|------|
| 客户自助理赔入口 | 前端 + 后端 2人 | 支持客户上传影像与填写基本信息 |
| 材料解析 Agent B | OCR 集成 + 多模态 LLM 调用 | 发票+诊断证明自动提取 |
| 结论汇总 Agent F + 人工授权 Gate | 前端 + 后端 1人 | 审核工作台 MVP |
| **试点险种**：1 款意外险或住院医疗险 | **预算参考**：~10~15 万元 | **目标**：小额案件分钟级处理 |

### Phase 2：核心能力建设（4~6 周）

| 模块 | 说明 |
|------|------|
| 核责判断 Agent C | RAG 条款知识库搭建 + 规则引擎接入 |
| 理算 Agent D | 理算规则配置 + 自动化理算 |
| 扩展险种 | 覆盖 3~5 款主力医疗险 |

### Phase 3：风控与进阶（4~6 周）

| 模块 | 说明 |
|------|------|
| 风控审查 Agent E | 反欺诈规则 + 图数据库关联查询 |
| A2A 深度优化 | 并行编排、回退策略、冲突消解 |
| 全险种覆盖 | 扩展至全部在售健康险产品 |

### Phase 4：持续运营（ongoing）

- 置信度阈值调优（基于人工反馈数据）
- 条款知识库持续更新
- 模型迭代与效果监控

## 六、技术选型建议

| 组件 | 推荐方案 | 备选方案 |
|------|----------|----------|
| **OCR** | PaddleOCR（开源，中文优） | Tesseract |
| **多模态大模型** | Qwen-VL / GLM-4V（性价比高） | Claude API（精度更高） |
| **RAG 框架** | LangChain + 向量库（Milvus/PGVector） | LlamaIndex |
| **LLM 推理** | 通义千问 API / DeepSeek API | 本地部署 Qwen2.5 |
| **规则引擎** | Drools（确定性逻辑） | 自研规则 DSL |
| **Agent 框架** | LangGraph / CrewAI（A2A 编排） | 自研消息队列方案 |
| **前端工作台** | React / Vue3 + Ant Design | - |
| **数据持久化** | PostgreSQL + 对象存储（MinIO） | - |
| **部署方式** | Docker 容器化，支持私有化部署 | - |

### SaaS 生态集成建议

参考国任模式，以下环节可直接采购 SaaS 服务降低初期投入：

1. **OCR 识别服务**：腾讯云 OCR / 百度 OCR（按量计费，无需自建）
2. **医疗单据审核**：云知声智能医疗审核 SaaS（中小保司专属方案）
3. **大模型 API**：通义千问 / DeepSeek（Token 计费，月费可控）

## 七、与行业方案的对照

| 维度 | 本方案 | 元保 | 慧择 | 太保灵析 | 国任 |
|------|--------|------|------|----------|------|

## 八、核心差异化价值

1. **A2A 标准化通信**：Agent 间通过标准化消息协议协作，非简单的函数串调，各 Agent 可独立演进、替换、扩缩
2. **全链路追溯**：从报案到结论汇总，每一步的推理过程、中间结果、置信度均持久化，人工可逐级下钻审查
3. **强制人工授权**：AI 仅生成"审核建议"和"审核报告"，任何赔付/拒赔都必须由核赔人员点击确认，真正的"人在环中"
4. **轻量可分期**：首期 6~8 周即可上线 MVP，后续逐个 Agent 迭代添加，避免大额一次性投入
5. **风控独立成环**：风控审查作为独立 Agent 而非附属模块，确保风控不因主链路优化而被削弱
