## 一、系统概述

### 1.1 系统架构

星盾 A2A 智能理赔助手采用 **6-Agent 协同 + 强制人工授权** 架构：

```
┌─────────────────────────────────────────────────────────────┐
│ 用户操作层                                                    │
│   H5 报案 → 上传影像 → 进度查询 → 确认结果                    │
└────────────────────────┬────────────────────────────────────┘
                         │
┌────────────────────────▼────────────────────────────────────┐
│ A2A Agent 协同层                                             │
│                                                             │
│  Agent A      Agent B      Agent C       Agent D            │
│  报案受理  →  材料解析  →  核责判断  →   理算               │
│                                                             │
│  Agent E       Agent F                                      │
│  风控审查  →  结论汇总                                      │
└────────────────────────┬────────────────────────────────────┘
                         │
┌────────────────────────▼────────────────────────────────────┐
│ 人工授权 Gate（强制节点）                                     │
│  审核工作台 → 通过 / 驳回 / 修改后通过                       │
│  全链路推理可追溯，每一步可下钻查看                           │
└─────────────────────────────────────────────────────────────┘
```

### 1.2 案件状态流转

```
DRAFT ──→ PROCESSING ──→ AGENTS_COMPLETED ──→ PENDING_REVIEW ──→ APPROVED
  ↑                                                    │              REJECTED
  └── 退回补充材料（重新从 DRAFT 开始）                   └── (驳回)
```

3. 全部完成后提示"报案成功"

**提交后**，案件出现在列表中，状态为 `待处理`。

## 四、步骤二：执行 Agent 链路

### 4.1 触发执行

在案件列表页，找到状态为 `待处理` 的案件，点击 **「执行Agent」** 按钮。

### 4.2 处理过程

系统自动依次执行 6 个 Agent，状态变化如下：

```
待处理 (DRAFT)
    │
    ▼
处理中 (PROCESSING)
    │  ├─ Agent A: 报案受理     → 验证报案信息完整性
    │  ├─ Agent B: 材料解析     → OCR 识别影像内容
    │  ├─ Agent C: 核责判断     → 匹配保险条款
    │  ├─ Agent D: 理算         → 计算赔付金额
    │  ├─ Agent E: 风控审查     → 反欺诈检测
    │  └─ Agent F: 结论汇总     → 生成审核报告
    │
    ▼
Agent完成 → 待人工审核 (PENDING_REVIEW)
```

每个 Agent 执行完成后，状态显示为绿色勾选，并标注置信度。

### 4.3 Agent 处理说明

| Agent | 功能 | 耗时 | 输出 |
|-------|------|------|------|
| **Agent A** 报案受理 | 校验报案信息，初始化案件 | ~1s | 结构化报案记录 |
| **Agent B** 材料解析 | OCR 识别影像、提取关键信息 | ~2s | 就诊日期、诊断、费用清单 |
| **Agent C** 核责判断 | 条款匹配、免责检查 | ~2s | 责任归属、排除项 |
| **Agent D** 理算 | 分项计算赔付金额 | ~2s | 理算明细、赔付总额 |
| **Agent E** 风控审查 | 反欺诈规则匹配 | ~1s | 风险评分、风险等级 |
| **Agent F** 结论汇总 | 聚合输出、生成报告 | ~1s | 审核报告 |

### 4.4 各 Agent 输出结果示例

**Agent B 材料解析输出：**
```json
{
  "documents_parsed": [
    {"type": "身份证", "status": "已识别", "confidence": 0.99},
    {"type": "诊断证明", "status": "已识别", "confidence": 0.97},
    {"type": "费用发票", "status": "已识别", "confidence": 0.95}
  ],
  "diagnosis": "急性阑尾炎",
  "medical_total": 12500.00

```

```json

  "exclusions_checked": [
    {"item": "既往症排除", "matched": false},
```


### 6.3 三种审核操作

| 操作 | 适用场景 | 说明 |
|------|----------|------|
| **✅ 通过** | AI 置信度高，材料齐全 | 一键确认，案件状态 → `已通过` |
| **❌ 驳回** | 材料不全、不在保障范围 | 需填写驳回理由，案件状态 → `已驳回` |
| **✏️ 修改后通过** | AI 理算金额有偏差 | 可修改理算金额，填写修改理由 |

### 6.4 审核决策参考

| 风险等级 | AI 置信度 | 建议操作 |
|----------|-----------|----------|
| 🟢 低风险 | ≥ 90% | 一键通过 |
| 🟡 中风险 | 70% ~ 89% | 逐项审核后决定 |
| 🔴 高风险 | < 70% | 建议驳回或转线下调查 |

### 6.5 审核完成

审核提交后不可撤回，系统记录审计日志：

### 8.2 curl 测试示例

```bash
# 1. 新建案件
curl -s -X POST http://localhost:8000/api/v1/cases \
  -H "Content-Type: application/json" \
  -d '{"insured_name":"张三","insurance_product":"住院医疗险A","incident_desc":"急性阑尾炎住院","incident_date":"2024-07-20","total_amount":12500}'

# 2. 上传影像
curl -s -X POST http://localhost:8000/api/v1/cases/1/documents \
  -F "file=@test_invoice.jpg" \
  -F "doc_type=invoice"

# 3. 查询影像列表
curl -s http://localhost:8000/api/v1/cases/1/documents | python -m json.tool

# 4. 执行 Agent
curl -s -X POST http://localhost:8000/api/v1/cases/1/run | python -m json.tool

# 5. 查看 Agent 链路
curl -s http://localhost:8000/api/v1/cases/1/traces | python -m json.tool

# 6. 提交审核（通过）
curl -s -X POST http://localhost:8000/api/v1/cases/1/review \
  -H "Content-Type: application/json" \
  -d '{"action":"approve","comment":"材料齐全，同意赔付","operator":"王丽"}'
```
